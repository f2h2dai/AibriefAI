# AIbrief Agent Operations Dashboard

AIbrief uses one `AgentOperationsOrchestrator` with five bounded workers. The workers do not schedule themselves, call each other, publish content, or operate X accounts. GitHub Actions remains the only production scheduler, and the existing connectors and Gemini/Groq fallback remain the source and summary pipeline.

## Worker boundaries

| Worker | Adapter responsibility |
| --- | --- |
| Signal Scout | Normalize already-collected records, annotate exact-title duplicates, and derive action-score inputs. |
| Brief Composer | Reuse existing English/Arabic summaries, attach evidence references, and apply full-brief or Saudi act-now output rules. |
| Brief Planner | Validate the requested mode and record that GitHub Actions owns scheduling. |
| Intelligence Analyst | Calculate run, quality, cost, source, and action-gate metrics from recorded data only. |
| Public Signal Watcher | Accept public X or user-exported bookmark records and reject DMs, protected content, and all write actions. |

Each worker returns a bounded dictionary to the orchestrator. A worker failure is recorded as `failed`, the run becomes `partial`, and the remaining workers continue with the last valid signal set.

## Action score and gate

The score is deterministic:

```text
relevance * 0.25 + novelty * 0.20 + evidence * 0.20 + urgency * 0.20 + user_fit * 0.15
```

An item is `act_now` only when its score meets the configured production threshold, it has at least two evidence links, it has a primary-source URL, it has zero unsupported claims, and it is not a duplicate.

Existing pipeline fields are preserved. Missing component scores receive documented deterministic defaults based on the existing score, freshness, evidence URLs, source type, and region. No corroborating URL or competitor value is invented.

## Metrics

`web/data/metrics.json` records the latest run. `web/data/runs.json` keeps the latest 30 run summaries. Both are generated by `.github/workflows/update-feed.yml` and committed with the existing feed artifacts.

The dashboard displays collected and verified signals, act-now items, duplicate rate, unsupported-claim rate, source failure rate, primary-source-link rate, daily recorded API cost, latest successful run, highest action score, source contribution, worker status, run history, and isolated source warnings. Notification precision remains null until reviewed outcome labels exist.

## Scenario slider

The slider runs entirely in the browser. It recalculates visible signals, act-now items, recorded cost, source distribution, and a deterministic false-positive-risk band for thresholds from 55 to 85. It has no save control, network write, storage write, or production-configuration path. Production continues to use `ACTION_SCORE_THRESHOLD`, defaulting to 70.

## Modes

- `global_ai`: English and Arabic full brief.
- `saudi_act_now`: Saudi-only Arabic act-now output; returns `No action required today.` when no item passes.
- `x_public_watch`: public X records only, read-only, signal queue output.
- `bookmarks_import`: user-provided export, analysis queue output.

Machine-readable mode and policy files live in `config/operations_modes.yaml` and `policies/`. They use JSON-compatible YAML so the standard library can validate them without a new dependency.
